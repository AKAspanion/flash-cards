# AI Create (F1–F4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:implement-with-subagents by default, or ga:implement. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the Add/Edit screen, let users make a deck from notes, a PDF or a photo (F1), get a suggested card back (F2), a suggested title/labels/color (F3), and a card quality check (F4).

**Architecture:** Four callable functions (`generateCards`, `suggestBack`, `suggestSetDetails`, `checkCardQuality`) built on the ai-foundation gateway (`aiCallable` + `aiJson`), with request/response types appended to `shared/ai-contracts.ts`. The app calls them through `useAiStore().run` + `callAi`; every result is a preview the user applies or discards, so nothing is saved until the user saves the set as today.

**Tech Stack:** App: Vue 3.5, Vuetify 4, Pinia 4, vue-i18n 11, Vite 8, Firebase JS SDK 13, Vitest 5, Playwright 1.64. Functions: Node.js `nodejs22`, `firebase-functions` v2, `firebase-admin`, `@anthropic-ai/sdk`, `zod`, Vitest. Emulators via `npx --yes firebase-tools@15.34.2`. CI: GitHub Actions (`.github/workflows/ci.yml`).

**Spec:** `docs/specs/2026-11-02-ai-features.md`

  readonly maxLabels: 3;

export interface DraftCard { front: string; back: string }

export type GenerateSource =
  | { kind: 'text'; text: string }

export interface GenerateCardsRequest { source: GenerateSource; count: 10 | 20 | 30 }

export interface SuggestBackRequest { front: string }

export interface SuggestSetDetailsRequest {

}
export interface SuggestSetDetailsResponse {
  title: string;                            // 1..40 chars
  labelIds: string[];                       // subset of request label ids, 0..3

}

export type CardIssue = 'too-long' | 'ambiguous' | 'multiple-facts' | 'answer-in-question' | 'typo';
export interface CheckCardQualityRequest { cards: { id: string; front: string; back: string }[] } // 1..200
export interface CardQualityFinding {
  cardId: string;                           // an id from the request
  issue: CardIssue;
  note: string;                             // one sentence, ≤ 200 chars
  rewrite: DraftCard[];                     // 1 card, or 2 when splitting
}
export interface CheckCardQualityResponse { findings: CardQualityFinding[] } // ≤ 1 finding per card

Model input (`AiPart[]` for `aiJson`): text → one `text` part via `wrapUserContent`; PDF or image → one `file` part (`mimeType` as validated, `base64` as sent) followed by a `text` instruction part. The provider adapter turns these into its own shapes. `maxTokens`: `generateCards` 16,000; the others 4,000.

Post-processing (server, after schema validation):
- `generateCards`: drop cards whose trimmed front or back is empty, whose front > 200 or back > 500 characters; keep at most `count`. If no cards remain, refund the reserved heavy action and return `{ cards: [] }`.
- `suggestBack`: a back > 500 characters or empty is `ai-bad-output`.
- `suggestSetDetails`: title trimmed and > 40 characters is `ai-bad-output`; `labelIds` keeps only ids present in the request, de-duplicated, first 3; `color` becomes `null` unless it is in `CARD_COLORS` (case-insensitive, returned in the `CARD_COLORS` spelling).
- `checkCardQuality`: drop findings whose `cardId` is not in the request or whose `rewrite` has 0 or more than 2 cards; keep the first finding per card.
