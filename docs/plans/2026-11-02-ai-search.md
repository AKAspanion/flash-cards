# AI Search by Meaning and Duplicate Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:implement-with-subagents by default, or ga:implement. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Pro users search all their cards by meaning and warn them about likely duplicate cards when they save a set.

**Architecture:** A Firestore trigger embeds each Pro user's cards with Vertex AI text embeddings into server-only `card-embeddings` docs (one per card) and removes them when cards or sets go away. Two callables behind the existing AI gateway use Firestore vector search (`findNearest`, cosine): `searchCards` (query → top 20 cards) and `findDuplicates` (a set's cards → pairs at ≥ 0.92 similarity). Results carry only ids and scores; the app fills in card text and set titles from the library it already has loaded.

**Tech Stack:** App: Vue 3.5, Vuetify 4, Pinia 4, vue-i18n 11, Firebase JS SDK 13, Vitest 5, Playwright 1.64. Functions: `nodejs22`, `firebase-functions` v2, `firebase-admin` (Firestore vector search), `@google/genai` (Vertex AI embeddings, Application Default Credentials), `zod`, Vitest. Emulators via `npx --yes firebase-tools@15.34.2`. CI: GitHub Actions (`.github/workflows/deploy.yml` changed to deploy indexes with rules).

**Spec:** `docs/specs/2026-11-02-ai-features.md`

/** One vector per text, in order. Batches by EMBEDDING_BATCH_SIZE. Vertex 429/5xx/timeout → AiError('ai-busy').
 *  When aiFake(): a deterministic 768-dim vector — each lower-cased word hashed into one dimension, counts summed, L2-normalised. */

// functions/src/search/vectorStore.ts
export interface Neighbor { setDocId: string; cardId: string; score: number }   // score = 1 - cosine distance
/** findNearest on card-embeddings where uid == uid, COSINE, `limit` results.

export function nearest(uid: string, vector: number[], limit: number): Promise<Neighbor[]>;

/** Embeds new/changed cards, deletes docs of removed cards; skips cards whose text is ''. */
export function indexSet(uid: string, setDocId: string, cards: CardText[]): Promise<void>;

- Given c1 is removed from the set, then `card-embeddings/s1__c1` is deleted.

- Given `embedTexts` in fake mode, then the same text always yields the same unit-length vector, `'hablar\nto speak'` and `'to speak hablar'` score 1.0 against each other, and texts with no shared words score 0.

- Given a Pro user with indexed cards, when `searchCards({ query: 'speak' })` runs, then the query is embedded with `RETRIEVAL_QUERY`, `nearest` is called with the caller's uid and limit 20, and hits come back highest score first with `setDocId`, `cardId`, `score` only.
- Given `ai-index/{uid}` is missing, when `searchCards` or `findDuplicates` runs, then `ensureBackfilled` indexes each of the user's non-trashed sets once and writes `backfilledAt`; on the next call it does nothing.
- Given Vertex returns 429 or 503 or times out during a search, then `unavailable` / `ai-busy` and the light action is refunded.
- Given `findDuplicates` with 301 cards, then `too-large` before usage is reserved; with a side of 1,001 characters, `too-large`.
- Given set s2 with cards d1 and d2 of identical text, and another set s1 holding a card c1 of the same text, then `findDuplicates({ setDocId: 's2', cards })` returns pairs (d1↔d2) once (not also d2↔d1) and (d1↔s1/c1), (d2↔s1/c1), each with `score` ≥ 0.92, highest first; stored embeddings of `s2` itself are never compared (the request's fresh vectors are used for in-set pairs).
- Given a pair scoring 0.91, then it is not returned; 0.92 is returned.
- Given more than 50 qualifying pairs, then the 50 highest are returned.
- Given any call, then no log line contains the query or card text.
