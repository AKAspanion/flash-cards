# AI Study Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:implement-with-subagents by default, or ga:implement. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Pro study features: smart review scheduling with a review log (F5), AI-graded typed answers (F6), an "Explain this card" chat (F7) and a weak-spot summary with practice cards (F8).

**Architecture:** Scheduling runs on the device: each card keeps an optional `srs` state inside the existing `cards` JSON string, `ts-fsrs` computes the next due date, and every rating writes a `reviews` document. A new review screen (`/:id/review`) studies due cards one at a time; typed-answer grading and the explain chat call two light callables, and the end-of-round summary screen calls one heavy callable that reads the set and its last 200 reviews on the server. All AI calls go through the ai-foundation gateway and store.

**Tech Stack:** App: Vue 3.5, Vuetify 4, Pinia 4, vue-i18n 11, vue-router 5, Vite 8, Firebase JS SDK 13, `ts-fsrs` (new), Vitest 5, Playwright 1.64. Functions: `firebase-functions` v2, `firebase-admin`, `@anthropic-ai/sdk`, `zod`, Vitest. Emulators via `npx --yes firebase-tools@15.34.2`. CI: GitHub Actions (`.github/workflows/ci.yml`).

**Spec:** `docs/specs/2026-11-02-ai-features.md`

**Depends on:** the ai-foundation plan (`docs/plans/2026-11-02-ai-foundation.md`) merged. It does **not** need the ai-create plan: the practice cards of F8 come back from the weak-spot call itself and open as a new draft set in the Add screen (see Task 5).

Prompting rules (described, not code):
- `gradeAnswer`: the system prompt states the grading rule from §9.9 verbatim; question, expected answer and typed answer each go through `wrapUserContent`; schema `{ verdict: enum, feedback: string ≤ 200 }`; `maxTokens` 4,000. Fixture: `correct` with feedback `Fake grading.` when the trimmed, lower-cased answer equals the trimmed, lower-cased expected answer, otherwise `incorrect` with the same feedback.
- `explainCard`: with no messages, the model writes an explanation with one example and one memory tip; with messages, it answers the last user question about the card. - `weakSpots`: reads `flash-card-sets/{setDocId}` with the Admin SDK and the user's last 200 reviews of that set (newest first). Per card still in the set it sends the front and back (each cut to 1,000 characters), the number of reviews and the count of each rating, and whether any typed answer was incorrect. Weak cards are those with any rating 1 or 2 or an incorrect typed answer. Schema: `topics` (≤ 3, `name` ≤ 60, `cardIds` from the cards sent), `tip` (≤ 600), `practiceCards` (≤ 5, front ≤ 200, back ≤ 500) aimed at the weakest cards. After parsing, unknown card ids are removed and topics left with no ids are dropped. `maxTokens` 16,000. Fixture: one topic `Fake topic` holding the first two weak card ids (or the first two cards when none are weak), tip `Fake study tip.`, and five cards `Practice question 1…5` / `Practice answer 1…5`.
