# AdSense Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: the project's workflow policy names the executor (`run.executor`): ga:implement-with-subagents by default, or ga:implement. Follow the policy and this plan's Checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show one Google AdSense banner at the bottom of Home and Info, with the CSP, `ads.txt` and privacy policy it needs, and nothing at all when its env vars are unset.

**Architecture:**
- **Task 1 (foundation):** `src/services/ads.ts` (config validation, script loading, ad request) and the two env vars.
- **Task 2:** `AdBanner.vue`, placed on Home and Info; consumes Task 1.
- **Task 3:** hosting: the CSP in `firebase.json` and `public/ads.txt`.
- **Task 4:** the privacy policy's new Ads section and changed wording.

Tasks 1, 3 and 4 start together; Task 2 follows Task 1.

**Tech Stack:** Vue 3, Vuetify 4, vue-i18n, TypeScript, Vite with `vite-plugin-pwa`, Firebase Hosting, Vitest (jsdom) with `@vue/test-utils`, GitHub Actions (`.github/workflows/deploy.yml`).

**Spec:** `docs/specs/2026-11-04-adsense.md`

## Global Constraints

- §2.1: "Every new or changed user-facing string is in both `src/locales/en.json` and `src/locales/hi.json`. The English is the copy in this spec, word for word." The implementer writes the Hindi; the PR lists it. `tests/unit/locales.spec.ts` checks the keys match.
- §2.2: "With either AdSense env var empty, the app behaves exactly as today: no script, no element, no request to a Google ad domain."
- §2.3: "An ad never blocks, shifts or breaks the app: a failed or blocked script, being offline, or an unfilled slot leaves nothing on screen and no error for the user."
- §2.4: "No new npm dependency."
- Unit tests are `tests/unit/<subject>.spec.ts` (Vitest, jsdom). A task runs only the tests it writes, each by name: `npx vitest run tests/unit/<file>`.
- Env vars are read through `import.meta.env` and typed in `src/env.d.ts`; tests set them with `vi.stubEnv`.

## Checkpoints

None. The policy sets `run.checkpoints: none`.

**Files:**

- Modify: `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: existing `import.meta.env` typing in `src/env.d.ts`.
- Produces (used by Task 2):

```ts
export type AdsConfig = { client: string; slot: string };
export const ADSENSE_SCRIPT_URL: string; // 'https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js'
export function adsConfig(): AdsConfig | null;
export function loadAdSense(client: string): void;
export function requestAd(): void;

declare global {
  interface Window { adsbygoogle?: unknown[] }
}
```

```ts
// src/env.d.ts, added to ImportMetaEnv
readonly VUE_APP_ADSENSE_CLIENT?: string;
readonly VUE_APP_ADSENSE_SLOT?: string;
```

**Spec:**
- §3.1: "`VUE_APP_ADSENSE_CLIENT` — the publisher ID, `ca-pub-` followed by digits."
- §3.1: "`VUE_APP_ADSENSE_SLOT` — the display unit's `data-ad-slot`, digits."
- §3.2: "Both are added, empty, to `.env.example` with a comment"; the comment reads `# Optional: Google AdSense banner; no ads when empty`.
- §3.2: "and to the `env:` block of `.github/workflows/deploy.yml` as `${{ vars.VUE_APP_ADSENSE_CLIENT }}` and `${{ vars.VUE_APP_ADSENSE_SLOT }}`. They are public values, like the Firebase web config, and are not added to the deploy job's required-vars check"
- §3.3: "A value that doesn't match its pattern (`^ca-pub-\d+$`, `^\d+$`) counts as empty (2.2), so a typo can't inject markup or load a script from a crafted URL."
- §4.1: "`loadAdSense(client)` — appends, once per page load,"; the element is an `async` script with `crossorigin` `anonymous` and `src` `https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=<client>`, appended to `document.head`.
- §4.1: "A second call is a no-op. A script `error` event is swallowed (2.3)."
- §4.1: "`requestAd()` — `(window.adsbygoogle = window.adsbygoogle || []).push({})`, inside `try`/`catch` that swallows the error (2.3)."

**Tags:** `security`, `failure-paths`

**Knowledge:** `operations/environment: VUE_APP_ADSENSE_CLIENT and VUE_APP_ADSENSE_SLOT are optional; unset means no ads`; `integrations/google-adsense: the app loads adsbygoogle.js only from src/services/ads.ts, with a validated publisher ID` (new concept).

**Acceptance:**
- Given `VUE_APP_ADSENSE_CLIENT=ca-pub-1234567890` and `VUE_APP_ADSENSE_SLOT=9876543210`, `adsConfig()` returns `{ client: 'ca-pub-1234567890', slot: '9876543210' }`.
- Given either var empty or unset, `adsConfig()` returns `null`.
- Given `VUE_APP_ADSENSE_CLIENT` of `ca-pub-123"><script>`, `pub-1234567890`, ` ca-pub-1234567890` or `ca-pub-` (no digits), `adsConfig()` returns `null`.
- Given `VUE_APP_ADSENSE_SLOT` of `12a34` or `1234 `, `adsConfig()` returns `null`.
- Given `loadAdSense('ca-pub-1234567890')` called three times, `document.head` holds exactly one `script` whose `src` is `https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-1234567890`, with `async` true and `crossOrigin` `anonymous`.
- Given the loaded script fires an `error` event, nothing throws and no error reaches `console.error`.
- Given `window.adsbygoogle` is unset, `requestAd()` leaves it an array of one `{}`.
- Given `window.adsbygoogle.push` throws, `requestAd()` does not throw.
- `.env.example` contains `VUE_APP_ADSENSE_CLIENT=` and `VUE_APP_ADSENSE_SLOT=` under the §3.2 comment; `deploy.yml`'s build `env:` passes both from `vars`, and its required-vars loop doesn't list them.

### Task 2: The banner on Home and Info

**Files:**
- Create: `src/components/AdBanner.vue`
- Modify: `src/views/Home.vue`
- Modify: `src/views/Info.vue`
- Test: `tests/unit/AdBanner.spec.ts`

**Interfaces:**
- Consumes: `adsConfig()`, `loadAdSense(client)`, `requestAd()` from Task 1; existing `useLibraryStore().status` (`'idle' | 'loading' | …` in `src/stores/library.ts`).
- Produces: `<ad-banner />`, a component with no props and no events.

**Spec:**
- §4.2: "Renders nothing when `adsConfig()` is `null`."
- §4.2: "Otherwise renders, inside a wrapper with the page's side margin and a small top margin:"; the element is an `ins` with class `adsbygoogle`, style `display:block`, `data-ad-client` the client, `data-ad-slot` the slot, `data-ad-format` `auto` and `data-full-width-responsive` `true`.
- §4.2: "then on mount calls `loadAdSense(client)` and `requestAd()` once."
- §4.2: "Each mount is a fresh `<ins>` and one push, so leaving and coming back to a screen asks for a new ad."
- §4.2: "An unfilled slot is hidden:" an `ins.adsbygoogle` whose `data-ad-status` is `unfilled` gets `display: none`, so no blank box stays.
- §4.2: "No label, close button or placeholder of its own; AdSense draws its own" marking.
- §4.3.1: "**Home** (`src/views/Home.vue`): below the sets list, as the last thing on the page, once sets have finished loading (not under the loading shimmer). Shown whether the list has sets or shows the empty state. Never between sets."
- §4.3.2: "**Info** (`src/views/Info.vue`): after the last card on the page."
- §4.3.3: "Nowhere else." The screens it names (study, add/edit, profile, settings, bin and the two public pages, and the entry screen) get no banner.

**Tags:** `failure-paths`, `not security: places a banner on two signed-in screens; touches no auth, session or user data`

**Knowledge:** `features/library: an AdSense banner sits below the sets list on Home once they have loaded, and AdBanner is the only place an ad is requested`; `features/settings-and-about: the Info screen ends with the AdSense banner`.

**Acceptance:**
- Given `adsConfig()` returns `null`, `AdBanner` renders no `ins` element, and neither `loadAdSense` nor `requestAd` is called.
- Given `adsConfig()` returns `{ client: 'ca-pub-1234567890', slot: '9876543210' }`, `AdBanner` renders one `ins.adsbygoogle` with `data-ad-client="ca-pub-1234567890"`, `data-ad-slot="9876543210"`, `data-ad-format="auto"`, `data-full-width-responsive="true"` and inline `display: block`; `loadAdSense` is called once with `'ca-pub-1234567890'` and `requestAd` once.
- Given the banner is unmounted and mounted again, `requestAd` has been called twice and each mount rendered its own `ins`.
- Given `requestAd` throws, mounting `AdBanner` does not throw and the page renders.
- The component's styles contain the `ins.adsbygoogle[data-ad-status="unfilled"]` rule with `display: none`.
- On Home, `<ad-banner />` is rendered after `.home__sets`'s list, only when `library.status` is neither `'idle'` nor `'loading'`; it is not inside the `transition-group`.
- On Info, `<ad-banner />` is the last element inside the page, after the last `v-card`.
- No other file under `src/views/` references `ad-banner` or `AdBanner` (a test greps `src/views/*.vue` and finds it only in `Home.vue` and `Info.vue`).
