- Produces:

```ts
// src/utils/verifyBanner.ts
export const VERIFY_BANNER_SNOOZE_DAYS = 7;
/** The localStorage key for one user's dismissal: `flashcards.verifyBannerDismissedAt.<uid>`. */
export function dismissKey(uid: string): string;
/** The dismissal time stored for `uid`, or null when none, unreadable, or storage throws. */
export function readDismissedAt(storage: Storage, uid: string): number | null;
/** Stores `now` as `uid`'s dismissal time; a storage that throws is ignored. */
export function writeDismissedAt(storage: Storage, uid: string, now: number): void;
/** True while fewer than VERIFY_BANNER_SNOOZE_DAYS days have passed since `dismissedAt`. */
export function isSnoozed(dismissedAt: number | null, now: number): boolean;

// src/stores/account.ts
/** Reloads the user and, when verified, sets session.user.emailVerified. No snack, no loading bar; false offline, on any error, or when the user changed. */
checkVerifiedQuietly(): Promise<boolean>;
```

Behaviour:
- While `session.user` is signed in and not verified, the banner shows on the route named `profile` always, and on the route named `home` unless `isSnoozed(readDismissedAt(localStorage, uid), Date.now())`. It shows on no other route.
- On `/profile` the actions are Resend email and I've verified, unchanged.
- On Home the actions are Resend email and Dismiss (`verify.dismiss`, en: `Dismiss`). Dismiss hides the banner at once, then calls `checkVerifiedQuietly()`. If it resolves true, the banner is gone everywhere (the user is verified). If false, `writeDismissedAt(localStorage, uid, Date.now())`, so Home shows it again once 7 days have passed. Offline, the check is skipped and the dismissal is stored.
- The dismissal is per user: another account on the same browser has its own.

**Spec:** [decisions/email-verification-reminder-only](../../knowledge/decisions/email-verification-reminder-only.md), quoting the developer, 2026-11-06:
- Decision: "show a dismiss button instead of i have verified button, this persistent banner should show up in profile alwasy but in home page show once, after dismiss show in 7 days keep dates in localstorage"
- Decision: "when dismissed is clicked, quietly check if the email is verified if yes good, if not save 7days timer to reshow the banner in home screen. in profile page it is persistent always until verified"

**Tags:** security, failure-paths, screen

**Knowledge:** features/email-verification: the banner shows always on `/profile` (Resend email, I've verified) and on Home until dismissed (Resend email, Dismiss); Dismiss quietly re-checks verification, otherwise stores the time under `flashcards.verifyBannerDismissedAt.<uid>` and Home shows it again after `VERIFY_BANNER_SNOOZE_DAYS = 7` days.

**Acceptance:**

- `readDismissedAt` returns null for a missing key, a non-number value, and a storage whose `getItem` throws; `writeDismissedAt` with a storage whose `setItem` throws does not throw.
- Given an unverified user, when Home loads with no dismissal stored, then the banner shows with Resend email and Dismiss, and no I've verified.
- Given an unverified user on Home, when Dismiss is pressed and the quiet check says not verified, then the banner hides, no snack shows, and `flashcards.verifyBannerDismissedAt.<uid>` holds the time.

- Given an unverified user, when `/settings`, `/stats`, `/bin` or `/info` loads, then no banner shows.
