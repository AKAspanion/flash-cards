# Decisions

<!-- GA-GENERATED:index -->

- [Deleting an account always confirms who you are first](account-deletion-confirms-identity.md) - Account deletion shows a can't-be-undone dialog, then always re-confirms identity (password, or a Google redirect followed by a final tap) before anything is deleted; there's no typed confirmation.
- [Delete account is online-only and clears the device cache](account-deletion-online-only.md) - Once Firestore keeps a persistent offline cache, Delete account refuses to run offline and, after the account is gone, clears the local cache the way sign-out does.
- [One AdSense banner, on Home and Info only](adsense-banner-ads.md) - The app shows ads through one manual, responsive AdSense display unit at the bottom of Home and of Info, never while studying; no Auto ads, and nothing loads unless both AdSense env vars are set.
- [Ad consent is AdSense's own Privacy & messaging banner](adsense-consent-by-google.md) - Consent for ads in the EEA, the UK and Switzerland comes from AdSense's own GDPR message, configured in the AdSense dashboard; the app ships no consent code of its own.
- [The Android package name is in.spanion.flashcards.twa](android-package-name.md) - The TWA's Android application id is in.spanion.flashcards.twa, the production domain reversed plus .twa; Google Play never lets it change after the first upload.
- [The app is called FlashCards](app-name-flashcards.md) - The product name is written "FlashCards" (capital C) in English everywhere it shows, and "FlashCards - Learn & Memorize" where a full name is used; the Hindi name stays फ्लैशकार्ड.
- [The app is for people aged 13 and over](audience-13-and-over.md) - The Play listing declares a target audience of 13 and over, and the privacy policy says the app isn't directed at children under 13, which keeps the app outside Google Play's Families policy.
- [Auth emails are sent by Firebase, not by our own backend](auth-emails-sent-by-firebase.md) - Verification and password-reset emails stay with Firebase's built-in sender; sending them from a Cloud Function through an email provider, to put the links on flashcards.spanion.in, was declined as too much overhead.
- [The bin keeps sets until the user deletes them](bin-keeps-sets-indefinitely.md) - Sets moved to the bin stay there indefinitely; nothing purges them automatically.
- [Unlink billing when the monthly budget is spent](budget-kill-switch.md) - Because the Blaze plan has no spending cap, a Cloud Function unlinks the billing account once actual spend reaches the budget, dropping the project to the free Spark limits.
- [Card text is rendered only through renderCardText](card-text-rendered-only-through-sanitizer.md) - Card text, which a shared set can take from a stranger, becomes HTML only in src/utils/markdown.ts, through markdown-it with raw HTML off and a private DOMPurify allowlist; links are http, https or mailto and images are https.
- [This repository's code is continued, not rewritten](codebase-is-continued.md) - The flash-cards code at the repository root is the project's own live codebase, adopted into ga on 2026-11-03; work builds on it in place rather than replacing or migrating it.
- [Deleted data is gone at once, and emailed requests are done within 30 days](deletion-is-permanent.md) - The Firebase project keeps no Firestore backups or point-in-time recovery, so a deleted account's data is gone immediately; people who can't sign in can email for deletion, done by hand within 30 days.
- [The app displays standalone, not fullscreen](display-standalone.md) - The web manifest's display mode is standalone, so the web app and the Android TWA both keep the status bar and avoid immersive mode's keyboard problems.
- [E2E tests run only before a deploy](e2e-only-before-deploy.md) - The Playwright e2e job is skipped on pull requests and runs only when deploy.yml calls CI, so every hosting deploy still waits for it.
- [Email verification is a reminder, not a gate](email-verification-reminder-only.md) - An unverified user uses the whole app and sees a reminder banner; nothing reads emailVerified to allow or refuse anything, and the banner stays off the full-height study and editor routes.
- [Google sign-in uses a popup, not a redirect](google-sign-in-popup.md) - signInWithPopup is used because browsers that partition third-party storage break signInWithRedirect when the app isn't served from the auth domain.
- [Google sign-in uses a same-origin redirect](google-sign-in-redirect.md) - Google sign-in uses signInWithRedirect with the auth domain set to the host serving the app, so it needs neither popups nor cross-site storage and works inside the Android TWA.
- [Labels cannot be deleted](labels-cannot-be-deleted.md) - Users create and rename labels but never delete them, so a set never points at a label that no longer exists.
- [Labels are deleted only with the account](labels-deleted-only-with-account.md) - The app never deletes a single label, but firestore.rules keeps the owner's delete on labels so that deleting an account can remove its labels from the browser.
- [Local ports live in the 2100 block](local-ports-2100-block.md) - Every port the project opens on the developer's machine — dev server, emulators, previews — is fixed in one contiguous block starting at 2100, so it can run beside the developer's other projects.
- [Rules and functions are deployed by hand](manual-rules-and-functions-deploy.md) - A push to master deploys hosting only; firestore.rules and the Cloud Functions are deployed deliberately by hand.
- [No analytics for now](no-analytics-yet.md) - The app collects no analytics; VUE_APP_MEASUREMENT_ID is passed to the Firebase config, but Analytics is never started.
- [The 2020 TWA's asset links are dropped](old-twa-asset-links-dropped.md) - The site no longer vouches for the older Android app com.flashcards.twa; assetlinks.json names only in.spanion.flashcards.twa, so any copy of the old app still installed shows a browser bar.
- [Compatibility with the original app is no longer required](original-app-compatibility.md) - The code still keeps the original app's Firestore schema, localStorage keys, VUE_APP_ env names and service-worker file name, but the original app is no longer in use, so those shapes may change.
- [Owners may list their own documents in every owned collection](owned-collections-owner-list.md) - user-stats and shared-sets join OWNED_COLLECTIONS, and their rules allow a list only when the query is limited to the owner field equal to the caller's uid, because Delete account finds each collection's documents with that query.
- [Password reset uses Firebase's hosted action page](password-reset-uses-firebase-action-page.md) - A password reset link opens Firebase's own action page to set the new password, then continues to /login, rather than an in-app reset screen.
- [Google holds the app-signing key; we keep only the upload key](play-app-signing-google-key.md) - The Android app uses Play App Signing with the Google-generated app-signing key; the developer keeps only the upload key, and no key upgrade to a self-supplied key is planned.
- [Account deletion and a privacy page ship with the TWA](play-compliance-in-twa-work.md) - Google Play rejects an app that lets people create accounts unless they can delete them in the app and from the web, and needs a privacy policy URL, so both are built as part of the TWA work; data export stays a separate feature.
- [The project installs with pnpm](pnpm-package-manager.md) - The web app and functions/ both install with pnpm, pinned by packageManager in package.json, each with its own overrides and build-script policy in a pnpm-workspace.yaml.
- [Every pull request is reviewed, Hindi included](pr-review.md) - The developer reviews every pull request before it merges, including every new or changed Hindi string.
- [Ankit Kumar Pandit is the privacy contact](privacy-contact.md) - The privacy policy and the account-deletion page name Ankit Kumar Pandit as responsible for users' data, reachable at panditankit1995@gmail.com.
- [Review counts are written after the set save](review-counts-after-set-save.md) - When the user leaves a review, the set saves first and the day's review count is written only if that save succeeded (or there was nothing to save), so a refused save never counts reviews that were lost.
- [A set's cards may not exceed 900,000 bytes](set-size-limit-900000-bytes.md) - A set is refused at save when its serialized cards pass 900,000 bytes of UTF-8, which keeps the set's Firestore document under its 1 MiB limit.
- [Spaced repetition uses SM-2, not FSRS](sm2-over-fsrs.md) - Cards are scheduled with an SM-2 variant because it is simpler to test and needs no per-user tuning; FSRS can replace schedule() later.
- [One splash, held until the first screen is ready](splash-held-until-ready.md) - A cold launch shows the native splash image throughout (Android, Chrome, then the web page), and the page hides it with one fade once the first screen has rendered, with no minimum time; the Android app self-grants its splash URI so Chrome 152+ accepts the handover.
- [The TWA is built with Bubblewrap, committed in android/](twa-built-with-bubblewrap.md) - The Android project is generated by the Bubblewrap CLI and committed under android/, while the signing keystore and its passwords stay outside the repository and the bundle is built and signed locally.
- [The Android app is portrait on phones, any orientation on large screens](twa-orientation.md) - The TWA declares portrait orientation; Android 16 ignores orientation locks on screens 600dp and wider for apps targeting API 36, so tablets and unfolded foldables rotate freely.
