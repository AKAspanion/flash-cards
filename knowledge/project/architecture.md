# Architecture

## Services

- **Web app** (`src/`): Vue 3, Vuetify, Pinia, Vue Router and vue-i18n, built by Vite into `dist/` and served
  by Firebase Hosting, which rewrites every path to `/index.html` (`firebase.json`). It is a PWA: the service
  worker is generated by `VitePWA` in `vite.config.ts`. See [flash-cards](../apps/flash-cards.md).
- **Firebase Auth and Firestore**: the only backend the app talks to. All calls go through
  `src/services/firebase.ts`; elsewhere the SDK is imported only for types and `Timestamp` (in
  `src/stores/session.ts` and `src/services/cardSetMapper.ts`). See
  [Firebase](../integrations/firebase.md).
- **Firestore security rules** (`firestore.rules`): the only server-side enforcement. See
  [roles](../security/roles.md).
- **Cloud Function** `billingKillSwitch` (`functions/`): independent of the app. See
  [functions](../apps/functions.md).

## Jobs and queues

The one background job is `billingKillSwitch`, triggered by messages on the Pub/Sub topic `budget-alerts` that
a Cloud Billing budget publishes to. The web app has no jobs or queues.

## Data flow

1. `src/main.ts` mounts `App.vue` with Pinia, the router, Vuetify and i18n, and registers the service worker
   (`setupPwaUpdates` in `src/pwa.ts`).
2. Before every navigation, `router.beforeEach` in `src/router/index.ts` waits for Firebase to restore the
   session (`getAuthUser`), stores it in the session store, starts loading the library, and redirects with
   `authRedirect`. A watcher (`watchAuthChanges`) handles sign-in or sign-out that happens outside navigation,
   such as in another tab, by resetting and reloading the library.
3. `useLibraryStore` (`src/stores/library.ts`) loads all of the user's sets and labels in one go
   (`fetchCardSets`, `fetchLabels`) and keeps them in memory. Views read from it; filtering and sorting happen
   in the browser (`filterAndSortSets` in `src/utils/cardSets.ts`).
4. Writes go through the store's actions (`createSet`, `saveSet`, `deleteSet`, `createLabel`,
   `renameLabel`), which call the service, then update the in-memory list only after Firestore accepted the
   write. On failure they show an error snack and resolve to `null` or `false`.
5. `src/services/cardSetMapper.ts` converts between the app's `CardSet` and the stored document. See
   [data model](../data/model.md).
6. `useSessionStore` (`src/stores/session.ts`) holds the user, the busy counter (`track`), online state, the
   snack bar and `unsavedChanges`. `usePrefsStore` (`src/stores/prefs.ts`) holds device-local settings in
   localStorage.
